## Configuration Files
### postgresql.conf -> Main Configuration File
* This is the primary configuration file that controls
    * Memory usage
    * Connection Settings
    * Logging
    * Query planner behaviour
    * Background processes
    * Default location for this on Ubuntu is `/etc/postgresql/<version>/main/postgresql.conf`

### pg_hba.conf -> Host Based Authentication File
* Controls who can connect, from where, and how they authenticate
* Default location for this on ubuntu is `/etc/postgresql/<version>/main/pg_hba.conf`
* Common methods for authentication are 
    * trust (No password)
    * md5 (Password is hashed)
    * peer (OS level user match, local only)

### pg_ident.conf -> User Mapping for Authentication
* Used when using peer or ident authentication. It maps OS users to db roles
* Default location for this on ubuntu is `/etc/postgresql/<version>/main/pg_ident.conf`

### auto.conf 
* This file is auto generated by ALTER SYSTEM commands and should not be edited manually

### pg_log/ or log_directory -> Log files
* If logging is enabled in postgresql.conf, the log files go here


## Accessing PSQL for the first time
* PostgreSQL uses "roles" for authentication and not system users
* By default, only the postgres role exists
* To change authentication to password for any user, go to pg_hba.conf file and change this 
    `local   all             all                                     peer` 
    to this
    `local   all             all                                     md5`
    Then restart postgresql (Using `sudo systemctl restart postgresql`)




## Check PSQL Service Status
* To check or restart psql service, use these commands
```
sudo systemctl start postgresql
sudo systemctl enable postgresql  # start on boot
sudo systemctl restart postgresql
```

## Basic Commands
* `\l`: lists databases
* `\du`: lists roles/users
* `\c dbname`: connect to a database
* `\dt`: list tables
* `\q`: Quit

## Common Commnds
### Create a new PSQL User
* Use this command to create a new user `create role avinash with login createdb password 'yourpassword';`
* To create a superuser, use `alter role avinash with superuser;`
* To create a new DB, use `create database test_db`

## Role vs User
* A role is just a group or a permission bucket
* A role with login privileges is a user account
* The same role can be duplicated across multiple users


## Create a Role with readonly permissions
```
    -- Create the role
    CREATE ROLE readonly;

    -- Grant read-only permissions to this role on all tables in a schema (e.g., public)
    GRANT CONNECT ON DATABASE your_db TO readonly;
    GRANT USAGE ON SCHEMA public TO readonly;
    GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly;

    -- Ensure future tables also grant read access
    ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO readonly;
```

## Create a user with no permissions
```
    CREATE USER user_name WITH PASSWORD 'your_secure_password';
```

## Assign a role to a user
```
    GRANT role_tba TO required_user
```

## Revoke Privileges
```
REVOKE SELECT ON ALL TABLES IN SCHEMA public FROM role_name;
```

## Default Databases
* template0 and template1 are the default system databases used during the creation of new databases.
* template1 is the default template used when we run `createdb mydb`. It is equivalent to `createdb mydb -T template1`
* Any new db is copied from template1, including its schema, extensions, and configurations
* template1 can be modified so the other new databases also implement these new changes
* template0 is an unmodifiable copy of the PSql system database. It is read-only and not meant to be changed
* template0 is used whenever we want to create a new DB with a clean slate, bypassing any changes made to template1


## Good Practices

### **Use Separate Roles for Administration and Applications**

* 🔐 **Do not use the default `postgres` user for apps.**
* 🧑‍🔧 Use `postgres` only for admin tasks (backups, creating databases, etc.).

### Create Roles/Users:

```sql
-- Login role with limited privileges
CREATE ROLE app_user WITH LOGIN PASSWORD 'secure_password';

-- Optionally limit privileges
-- No CREATEDB, CREATEROLE, SUPERUSER unless needed
```

---

### **Use Databases per App or Microservice**

* Each application should ideally have its own database.
* Avoid shared schemas unless apps are tightly coupled.

---

### **Use a Dedicated Schema If Sharing a DB**

```sql
CREATE SCHEMA my_app_schema AUTHORIZATION app_user;
```

* Use schemas to isolate data within a shared database.

---

### **Restrict Permissions**

Limit access based on the principle of **least privilege**:

```sql
REVOKE ALL ON DATABASE myapp FROM PUBLIC;
GRANT CONNECT ON DATABASE myapp TO app_user;

\c myapp

REVOKE ALL ON SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA my_app_schema TO app_user;
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA my_app_schema TO app_user;
```

---

### **Enable Password Authentication**

Edit `/etc/postgresql/<version>/main/pg_hba.conf`:

```conf
# Instead of trust
local   all             all                                     md5
host    all             all             127.0.0.1/32            md5
```

Then:

```bash
sudo systemctl reload postgresql
```

---

### **Use Environment Variables for Credentials**

Never hardcode DB credentials in code. Use:

* `.env` files (and python-dotenv)
* AWS Secrets Manager / HashiCorp Vault (for production)

---

### **Backups and WAL Archiving**

Use `pg_dump` and `pg_basebackup`:

```bash
pg_dump -U postgres mydb > backup.sql
```

For continuous backup, consider:

* WAL archiving
* Tools like **pgBackRest** or **Barman**

---

### **Monitoring and Logs**

Enable logging:

```conf
# In postgresql.conf
logging_collector = on
log_directory = 'log'
log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
```

Use monitoring tools:

* `pg_stat_statements`
* `pgBadger`, `Prometheus`, `Grafana`

---

### **Regular Maintenance**

* `VACUUM` and `ANALYZE` to avoid bloat
* Use `autovacuum`, but tune it for high-write databases

---

### **Security Hardening**

* Disable remote access unless needed (`listen_addresses = 'localhost'`)
* Use firewalls (e.g., `ufw`) to restrict access
* Enforce SSL for remote connections

---

### **Use Connection Pooling**

Especially in high-load environments:

* Use `pgbouncer` or `pgpool-II`

---

### **Performance Tuning**

Update `postgresql.conf` for production:

```conf
shared_buffers = 25% of RAM
work_mem = 4-64MB (based on queries)
maintenance_work_mem = 128-512MB
effective_cache_size = 50-75% of RAM
```

---

### **Keep It Updated**

Use:

```bash
sudo apt upgrade postgresql
```

Or enable unattended upgrades if in a controlled environment.
